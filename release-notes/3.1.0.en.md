Ugurugu 3.1.0 adds round pixel brushes, keeps work from being lost when
the window closes, Windows signs out or shuts down, or a tab is closed
during an export, and makes the canvas and playback match the export
again.

## New

- Pixel mode has a round pixel pencil and a round pixel eraser. They draw
  in whole pixels like the pixel pencil, but each press covers the pixels
  inside a circle, so a wide stroke has round ends instead of square
  blocks.

## Fixed

- Closing the window or installing an update while an export was running
  stopped the export without asking. Ugurugu now asks whether to close when
  the export is done, to stop it and close, or to stay open.
- Closing the tab of a project being exported made the export fail. The
  export now finishes.
- Closing the window while a project was being saved or opened did nothing.
  The window now closes once the save or the opening is done.
- When Windows signed out, restarted or shut down, changes made in the last
  few seconds were not kept for recovery. They are now written before
  Ugurugu is ended and offered back at the next start.
- A settings file that could not be read was replaced by the defaults the
  next time a setting changed, losing the old settings, shortcuts and panel
  layout. It is now kept beside the new one, named
  `settings-unreadable-<date>.json`, and Ugurugu says so when it starts.
- A recovery folder that could not be read stopped automatic recovery for
  the whole window. It is now skipped and the rest is kept as usual.
- Two windows starting at the same moment could leave one of them without
  automatic recovery.
- When saving work for recovery kept failing, Ugurugu tried again every few
  seconds even with nothing changed. It now tries again once the work
  changes, or after 30 seconds.
- Recovery folders left by an unfinished write were never removed.
- With the wobble amount at 0, broken lines and sprays whose particles move
  on every frame could stand still on the canvas and in playback, though
  the export moved them. They now move in all three.
- When memory was short, fill and selection tools that read every visible
  layer or the reference layers saw the document's background colour in
  empty areas instead of transparency, so a fill could stop at the wrong
  edge.
- In a project that has reached its edit limit, a transform or text that
  could not be applied was left pending when you switched to another tab,
  opened a document or closed a tab, and recovery did not keep it. The tab
  now stays shown and Ugurugu asks you to apply or cancel it first.
- When a copy or cut could not be put on the Windows clipboard, nothing
  said so. Ugurugu now says that other apps cannot paste it; it still
  pastes in Ugurugu.
- Uninstalling removed other apps' entries in the `.ugurugu` "Open with"
  list, or left Ugurugu's own entry when another app had become the
  default. Only Ugurugu's entries are removed now.
- Screen readers now name the document on each tab's close button.

## Changed

- Copying or cutting a large selection no longer holds up drawing and the
  canvas while the copy is made for other apps.
- Recovered work that could not be read is kept for 30 days, then removed.
