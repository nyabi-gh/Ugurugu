Ugurugu 3.0.3 keeps work from being lost when the window closes, Windows
signs out or shuts down, or a tab is closed during an export, and keeps
settings and recovery files in order.

## Fixed

- Closing the window or installing an update while an export was running
  stopped the export without asking. Ugurugu now asks whether to close when
  the export is done, to stop it and close, or to stay open.
- Closing the tab of a project being exported made the export fail. The
  export now finishes.
- Closing the window while a project was being saved or opened did nothing.
  The window now closes once the save or the opening is done.
- When Windows signed out, restarted or shut down, changes made in the last
  few seconds were not kept for recovery. They are now written before
  Ugurugu is ended and offered back at the next start.
- A settings file that could not be read was replaced by the defaults the
  next time a setting changed, losing the old settings, shortcuts and panel
  layout. It is now kept beside the new one, named
  `settings-unreadable-<date>.json`, and Ugurugu says so when it starts.
- A recovery folder that could not be read stopped automatic recovery for
  the whole window. It is now skipped and the rest is kept as usual.
- Two windows starting at the same moment could leave one of them without
  automatic recovery.
- When saving work for recovery kept failing, Ugurugu tried again every few
  seconds even with nothing changed. It now tries again once the work
  changes, or after 30 seconds.
- Recovery folders left by an unfinished write were never removed.

## Changed

- Recovered work that could not be read is kept for 30 days, then removed.
