Ugurugu 3.0.1 fixes problems found after 3.0.0. Ugurugu 3.0.0 offers the
update by itself, or you can install it with the Setup file below.

## Fixed

- Saving over an existing project could, rarely, leave neither the old nor
  the new file, when another program such as antivirus or a sync client held
  the new file at that moment. The old file is now kept until the new one is
  in place.
- Changing a layer while a selection was being moved or transformed undid
  the move: renaming, hiding, opacity, blend mode, clipping, moving,
  grouping, merging down or deleting. Fill Selection, Invert Selection,
  adding to or taking from the selection, the magic wand and the fill bucket
  also used the selection from before the move. All of them now apply the
  move first.
- While Ugurugu asked about unsaved changes or showed a file dialog, a
  project opened from File Explorer could switch the tab shown, and the
  answer went to that project instead: **Don't Save** could close another
  project with unsaved changes, and **Save As** could save the other one.
  A project opened meanwhile now waits until you answer. The same switch
  could freeze the window while the GIF or WebP export options were open.
- **Save As** onto a file that is open in another tab is refused, instead
  of leaving two tabs that save over each other.
- After an unexpected error while drawing the window, the window froze and
  could not be closed. It now closes with an error message, and the next
  start offers the work kept for recovery.
- An export stopped by an unexpected error stayed in progress forever. It
  now ends with an error message.
- After changing the number of frames, the canvas could keep showing the
  poses for the old number with Smooth or Stepped motion, while export used
  the new one.
- **Ctrl+Plus**, **Ctrl+Minus** and **Ctrl+0** zoomed the whole interface
  when a text field, dialog or menu had the keyboard. They now only zoom the
  canvas.
