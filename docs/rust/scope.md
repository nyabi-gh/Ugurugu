## 1. 측정·개발 환경

| 항목 | 값 | 상태 |
|---|---|---|
| OS | Windows 11 Pro x64 (10.0.26300) | 확정 |
| CPU / RAM | Intel Core Ultra 7 270K Plus / 32GB (31.3GiB 인식) | 확정 |
| 주 모니터 | 3840×2160, 60Hz, 150%(144 DPI), NVIDIA GeForce RTX 5080 (드라이버 32.0.16.1714) | 확정 |
| 보조 모니터 | 2560×1440, 155Hz, 100%(96 DPI), Intel Graphics iGPU (32.0.101.8991) | 확정 |
| 입력 | **마우스만.** 펜 장치 없음 | 확정 |
| Rust | 1.99.0 stable, `x86_64-pc-windows-msvc`, edition 2024 | 제안 |

두 모니터가 서로 다른 GPU에 연결돼 있다. 창이 모니터를 옮길 때의 DPI 변경과 surface가 다른 adapter로 넘어가는 경우를 이 PC에서 그대로 시험한다. 기준선과 성능 목표는 주 모니터(UHD 60Hz) 기준으로 기록하고, 155Hz 모니터는 별도 행으로 남긴다.

## 2. 펜 없이 진행하는 방식

입력 경로는 처음부터 Win32 Pointer API(`WM_POINTER*`)로 만들고, 마우스도 `EnableMouseInPointer`로 같은 경로에 넣는다. 마우스용 경로를 따로 두었다가 펜 때 교체하지 않는다. 그래서 history 재정렬·중복 제거·capture·창 밖 버튼 해제·DPI 좌표 변환은 마우스로 지금 검증한다.

장치가 있어야만 확인되는 항목은 **미검증**으로 남기며 통과로 표시하지 않는다.

| 항목 | 마우스로 검증 | 펜 장치 필요 |
|---|---|---|
| sample history 정렬·중복·유실 | O | 펜 sample rate에서 재확인 |
| capture, 창 밖 버튼 해제, Alt+Tab, 포커스 상실 | O | 재확인 |
| DPI가 다른 모니터 이동 | O | — |
| 필압·유효성 mask, pressure=0 처리 | 경로만 (pressure 미지원으로 보고) | O |
| hover, 펜 뒤집기(지우개), barrel button | — | O |
| WinTab | — | O |

필압이 없는 입력의 기본 압력은 브러시 설정의 명시적 값으로 처리한다. 0으로 그리지 않는다.

## 3.1 렌더러 (2026-10-06 확정)

| 항목 | 결정 |
|---|---|
| 문서 래스터화·합성 | **Vello CPU 0.3.0** (`u8_pipeline`). 실시간 획 한 칸은 1스레드 context, 재생·전체 다시 그리기는 다중 스레드 context. 같은 입력이면 스레드 수와 관계없이 바이트 단위로 같으므로 미리보기와 내보내기가 같은 경로를 쓴다. SIMD 수준은 SSE4.2로 고정해 CPU가 달라도 같은 픽셀을 낸다 |
| 화면 표시 | wgpu DX12. CPU 결과의 dirty rect만 텍스처로 올리고 표시·확대·오버레이만 GPU가 맡는다 |
| Vello GPU | **보류.** 재생 성능이 부족하다고 측정되면 재생 경로에 한해 검토한다. GPU·드라이버마다 결과가 달라질 수 있어 내보내기 경로로는 쓰지 않는다 |
| 제외 | tiny-skia(1스레드 래스터화가 Vello의 3.4배 느림), Vello compute(upstream 실험 단계), skia-safe(C++ 빌드 체인), Direct2D(COM·장치 손실 비용, GPU 결과 비결정성) |

근거는 [m0-evidence.md](m0-evidence.md) 6절이다.

## 3.2 GPU 조건과 fallback (2026-10-07 확정)

| 항목 | 결정 |
|---|---|
| 최소 사양 | 하드웨어 DX12 어댑터. 표시는 wgpu DX12만 쓴다 |
| WARP | 하드웨어 어댑터가 창을 표시할 수 없으면 WARP로 연다. 상태 표시줄에 "느린 소프트웨어 표시" 안내를 띄운다. 문서 렌더·저장·내보내기는 CPU 렌더러라 그대로 동작한다. 진단용으로 `UGURUGU_ADAPTER=warp`로 강제할 수 있다 |
| 장치 손실 | 장치·스왑체인·GPU 자원을 모두 버리고 새로 연다. 문서와 캔버스 래스터는 CPU에 있으므로 잃지 않는다. 실제 드라이버 리셋(TDR) 시험은 M3 장치 손실 통과 조건에서 한다 |
| 원격 세션(RDP) | M6 배포 시험(깨끗한 VM 포함)에서 확인한다 |

근거는 [m0-evidence.md](m0-evidence.md) 8절이다.

## 4. 제외

구형 `.ugu`(schema 1~13)·`.wagle`·`.wobble`·`.wawa`·`.wwpreset` 읽기, 이전 설정·프리셋·복구본 이관, Qt 클립보드 형식, macOS·모바일·웹(WASM·Svelte), C++ 엔진 FFI. 구형 파일은 "지원하지 않는 형식" 판별만 한다.
