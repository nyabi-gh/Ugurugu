# 레이어 외곽선 계획

2026-11-08 작성. 이슈 #157의 제안 3(레이어 외곽선, backlog B3-171)을 다룬다. 사용자 결정(2026-11-08): 이 계획서를 먼저 쓰고, 시제품으로 잰 뒤 방식을 정한다. 같은 계획에 있던 제안 4(페이드)는 구현했다(decisions.md 4절). 이 문서는 계획이다. 정한 것은 구현하면서 decisions.md로, 측정은 evidence.md로 옮기고, 끝나면 이 문서를 지운다.

코드 위치는 main `b0bea95`를 읽은 것이다. 비용·모양에 관한 문장은 재기 전이라 모두 **가설**이다.

## 1. 지켜야 할 약속

1. **화소 일치**: 캔버스·재생·내보내기는 한 `RenderPlan`을 평가하고, 원래 크기에서 캔버스와 내보내기가 바이트 같다(decisions.md 2절). 새 계산은 렌더 쪽 한 곳에만 두고 화면 전용 근사를 만들지 않는다.
2. **성능은 8 작업자로 잰다**: `UGU_WORKER_THREADS=8`, `ugu-doc render <file> 8`. 전후를 같은 방법으로 잰다.
3. **안 쓰면 바이트가 그대로**: 기능을 쓰지 않은 문서는 저장 바이트와 fixture digest가 전과 같다. 쓴 문서는 manifest `required`에 기능 이름을 넣어 옛 판이 "새 판에서 만든 파일"로 거절한다(ADR 3.2.0·3.3.0과 같은 방식).
4. **그리는 중과 확정이 같다**: 그리는 중인 획, 펜을 뗄 때 찍는 획(`compose.rs` `Stamp`), 전체 렌더가 같은 모양이다(decisions.md 2절).

## 2. 지금 코드

- 페인트 레이어(`ugu-core` `ops.rs` `PaintLayer`)는 연산 목록이다: `Paint`(획), `Erase`(지우개), `Fill`(만들 때 고정한 coverage), `PlaceImage`, 선택 변형, 자르기·크기 바꾸기. 획만 있는 게 아니다.
- 합성(`ugu-render` `composite.rs`)은 레이어마다 원본(source) 하나를 받아 `Put` 프로그램(`Begin`·`End`·`Over`·`Backdrop`·`Base`)으로 겹친다. 레이어 원본은 revision이 같으면 다시 쓴다(`document.rs`). 우글거림이 꺼진 레이어는 한 번만 그린다.
- 획의 굵기는 표본마다 `(폭 × 필압 계수).max(가장 가는 폭) × 0.5`이다(`stroke.rs`의 반폭 계산, `Pen::thinnest`는 안티앨리어싱 0.5px, 아니면 1px). 폭은 프레임마다 우글거림으로 변한다(`Pen::width_on`).

## 3. 외곽선 (B3-171)

### 3.1 권장 방식: 레이어 효과

레이어 속성 `outline { width, color, opacity }`. 그 레이어를 그린 원본의 알파에서 바깥쪽 거리를 구해(정확한 유클리드 거리 변환, EDT), 거리가 `width` 이하이고 원본이 덮지 않은 곳을 색으로 칠해 레이어 아래에 깐 뒤 같은 `Put`으로 합성한다. Photoshop의 레이어 Stroke "바깥"과 같은 모양이고, 지우개·채우기·이미지를 포함한 결과 전체에 테두리가 생긴다.

- 위치는 처음엔 "바깥"만. "안"·"가운데"는 요청이 생기면 더한다.
- 폭은 문서 px로 1~250. 이슈의 Photoshop 범위(1~250)를 따른다. 재생의 축소 렌더에서는 폭도 같은 비율로 줄인다.
- 계산 범위는 레이어의 경계 사각형에 폭을 더한 영역. EDT는 행과 열로 나뉘는 두 번의 1차원 변환이라 작업자에 나눠 줄 수 있다.
- 처음엔 페인트 레이어만. 그룹 레이어의 외곽선(그룹 합성 결과에 두름)은 뒤로 미룬다.

### 3.2 고려했다가 권하지 않는 방식: 획마다 외곽선

넓힌 획을 원래 획 아래에 한 번 더 그린다. 레이어의 획을 "넓힌 획 전부 → 원래 획 전부" 두 번 그리면 겹친 획끼리 테두리가 서로를 덮지 않는다. 다만 `Erase`·`Fill`·`PlaceImage`에는 맞지 않는다. 지운 자리를 넓혀도 지운 모양의 테두리가 되지 않고, 채우기와 이미지는 넓힐 획이 없다. 레이어에 획만 있다는 보장이 없어서 권하지 않는다.

### 3.3 측정 (시제품)

형식과 UI 없이, 시제품 브랜치에서 `ugu-render`에 외곽선 단계를 붙이고 `ugu-doc render`가 환경 변수(예: `UGU_OUTLINE=<폭>`, `UGU_OUTLINE_LAYERS=one|all`)로 켠다. 이 브랜치는 머지하지 않는다.

| 잴 것 | 조건 |
|---|---|
| 프레임 시간 p50·p95 | fixture ②(2048², 페인트 14)·⑤(4096²), 8스레드와 1스레드, 외곽선 없음 / 가장 큰 레이어 하나 / 모든 페인트 레이어, 폭 4·32·250 |
| EDT 단독 시간 | 2048²·4096² 알파, 8스레드 |
| 프로세스 최대 메모리 | 위와 같은 조건, 외곽선 없음과 비교 |
| 우글거림 꺼진 레이어 | 두 번째 프레임부터 외곽선을 다시 계산하지 않는지(revision 재사용) |
| 화소 | 같은 문서에서 `render`(캔버스 경로)와 내보내기의 digest가 같은지 |

판정 기준(제안, 사용자가 고칠 수 있다): 8스레드 ②에서 가장 큰 레이어 하나에 폭 32를 켰을 때 프레임이 +10% 이하이면 3.1대로 구현한다. 넘으면 그 숫자를 가지고 폭 상한, 경계 사각형 축소, 재생 때 축소 해상도에서만 계산(내보내기는 원래 크기) 중에서 다시 정한다. ②는 8스레드에서 이미 30fps 목표를 넘는다(backlog B3-70).

### 3.4 결과 (2026-11-08, evidence.md 109절)

8스레드 3 round의 p50 중앙값으로 ② 가장 큰 레이어 하나·폭 32는 처음 +56%, 계산을 줄인 뒤 +20%다(round별 +13~+27%). 판정 기준 +10%는 아직 넘는다. 외곽선 단계는 22.5 → 6.2 ms로 줄었고 화소 결과는 같다. 이 비용은 외곽선을 켠 레이어에만 든다.

남은 일:

1. 3.3의 판정을 사용자와 다시 정한다. 권장: 켠 레이어에만 드는 비용이니 3.1대로 만들고, 아래 2·3은 구현 때 잰다.
2. 우글거림이 꺼진 레이어의 재사용은 `ugu-doc render`로 잴 수 없다. revision 없이 그려 매 프레임 레이어를 다시 그리므로 revision을 넘기는 측정이 따로 필요하다. 외곽선을 레이어 캐시에 담으면 이런 레이어는 두 번째 프레임부터 이 비용이 들지 않을 것으로 본다(가설).
3. 화소 일치는 재지 못했다. 시제품은 `render_scaled`에만 붙어 있고 표면 예산을 넘는 경로(`render_streamed`)에서는 멈춘다.

## 4. 형식

schema 1에 선택 필드를 더한다.

| 위치 | 필드 | `required` | 쓰지 않으면 |
|---|---|---|---|
| 페인트 레이어 | `outline: { width, color, opacity }` | `layer-outline` | 생략 |

읽기 검증에 범위(폭 1~250)를 더한다. 2.x 가져오기에는 대응하는 값이 없어 늘 생략한다.

2. 아래 "정할 것"을 사용자와 정한다.
3. 정한 대로 구현: 형식·렌더·세션·UI(도구 설정과 레이어 속성), `strings.txt` 네 언어, 릴리스 노트, 도움말, Sandbox `gui` 단계(화면 화소로).
4. 결정을 decisions.md로 옮기고 이 문서와 backlog 행을 지운다.
