M6는 장치에 묶인 두 gate를 열어 둔 채 끝난다. 이어서 사용자 질문으로 빠져 있던 2.2.13의 필압 켜고 끄기를 넣었다(6절). 사용자가 쓴 분석 보고서(`docs/analysis-3.0.md`)의 A-01~A-05와 UI 지적을 확인해 고쳤고, 그리는 동안 재생을 2.2.13처럼 획이 끝나면 다시 재생하게 했다(2절 22·23, 6절).

M6 종료 조건(계획 11절): 깨끗한 PC 설치와 N→N+1 업데이트, 지원 펜/GPU 행렬, 레거시 의존 0. 이를 다음 다섯 가지로 확인한다.

- 깨끗한 Windows 11(Windows Sandbox)에서 설치물로 설치·실행·파일 연결·업데이트(N→N+1)·제거가 된다. 오프라인·업데이트 실패·취소에서 문서를 잃지 않는다.
- 2.2.13과 3.0을 한 PC에 함께 설치해도 서로의 설치·설정·복구·파일 연결을 건드리지 않는다.
- 3.0 앱의 빌드·실행·패키지가 C++·Qt 파일을 요구하지 않고, 배포 파일 목록과 `cargo tree`에 승인하지 않은 네이티브 의존이 없다.
- M5에서 넘긴 성능 항목(선택 이동 재생, 시작 어댑터 나열)을 재고 고치거나, 고치지 못한 이유를 기록한다.
- 펜·터치는 합성 입력(`InjectSyntheticPointerInput`)으로 코드 경로를 시험한다. 실제 장치 확인은 장치가 생길 때까지 열린 gate로 남기고, 통과로 적지 않는다.

범위는 계획 10.3·11·12절의 M6 행, scope.md의 M6 항목(업데이트, RDP, 터치 gate), M5에서 넘긴 것([m5-plan.md](m5-plan.md) 6절 M5-15 행, [m0-evidence.md](m0-evidence.md) 14·23절)이다. 2.2.13 동작은 C++ 소스에서 확인했다(각 행에 파일, 경로는 `src/` 아래).

일정: 3.0 출시 목표는 2026년 10월이다(사용자, 2026-10-10). 남은 기간이 약 3주라, 외부 조건(펜·터치 장치)에 묶인 것은 출시를 막는 일이 되지 않도록 5절에 따로 둔다.

## 3. 측정에서 시작하는 항목

### 선택 이동이 쌓인 레이어 (M5-15에서 넘김)

지금 구현(`ugu-render/src/document.rs`의 `Step::Move`): 이동을 만나면 그 앞까지의 Vello 실행을 끊고 그린 결과(`so_far`)를 이미지로 만든 뒤, 마스크로 자른 레이어 안에서 변환한 이미지로 다시 그린다. 소수 이동은 `ImageQuality::Medium`(bilinear)이다. 그래서 이동 하나가 (가) 실행 끊기와 표면 전체 래스터화, (나) 결과 복사, (다) 전체 크기 이미지 샘플링을 더한다. 레이어가 우글거리면 이동 앞의 결과가 프레임마다 달라 캐시할 수 없다.

먼저 N개 이동 문서로 이동 하나의 비용(약 21ms)을 (가)·(나)·(다)로 나눈다. 후보와 판정:

| 후보 | 기대 | 확인할 것 |
|---|---|---|
| 정수 평행 이동을 행 복사로 | (다)를 없앰 | Vello `Low` 경로와 바이트 동일 |
| 소수 평행 이동을 상수 가중치 bilinear로 직접 | (다)를 몇 배 줄임 | Vello `Medium` 샘플링의 산술(반올림·premultiplied·가장자리)을 그대로 따라 바이트 동일이 되는지. 안 되면 버린다 |
| 샘플링 범위를 이동 앞 내용의 범위와 마스크의 교집합으로 | 성긴 레이어에서 (다) 감소 | 내용 범위 계산이 이미 있는 `op_bounds`로 되는지 |
| 이어진 이동 합치기 | 이동 수 감소 | 2절 1. 바이트가 같은 경우만 |
| 실행 끊기 없이 이어 그리기 | (가)·(나) 감소 | Vello에서 끊지 않고 이전 결과를 읽을 방법이 있는지 |

### 시작 어댑터 나열

m0-evidence 14절: 어댑터 4개 각각의 첫 `D3D12CreateDevice`(NVIDIA 155~172ms, iGPU 109~123ms 등). 미리 열기로 첫 프레임이 약 480ms. 가끔 +500ms 실행이 있고 원인은 나누지 않았다. headless 도구로 wgpu 고정판·최신판의 나열 시간을 재고, 하나만 여는 길이 있는지 본다.

### 2.2.13 ③ 채우기 클릭→화면

m0-evidence 13절: 2.2.13은 ③(2048²)에서 12개 지점 모두 30초 안에 화면이 바뀌지 않았다. 원인 후보는 참조 이미지 준비(프레임당 약 4.5초)와 칠할 수 없는 지점이다. headless(`ugurugu_render_benchmark` 또는 작은 C++ 측정)로 참조 준비 시간을 먼저 재고, 클릭 지점을 칠할 수 있는 곳으로 고른 뒤 GUI로 잰다.
