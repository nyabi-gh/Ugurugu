# 계획: 한 창 안의 문서 탭과 UI 다듬기 (3.0)

두 일 모두 3.0 출시 전에 한다. 문서 탭은 1~6절, UI 다듬기는 7절.

2026-10-12 사용자 요청. 클립 스튜디오처럼 한 창에 캔버스 여러 개를 띄워 두고 탭으로 오간다. 지금은 새로 만들기·열기가 창의 문서 하나를 바꿔 끼우므로, 작업 중인 그림을 저장하거나 버려야 한다. 사용자가 3.0에 넣기로 정했다(출시는 그만큼 늦어진다). 상태는 이 문서 끝의 "진행"에 적고, 끝나면 결정은 decisions.md, 측정은 evidence.md로 옮긴 뒤 이 문서를 지운다.

## 1. 지금 구조 (2026-10-12, `1662f1e`에서 확인)

- 프로세스 하나에 창 하나, 문서 하나. `App`(`apps/ugurugu/src/app.rs`)이 `Session` 하나(winit 창, AccessKit, `PointerInput`, 렌더 스레드)를 가지고, `window_event`는 `WindowId`를 보지 않는다. "여러 창"은 프로세스 여러 개다(decisions.md M5 결정 13). 새 창을 여는 메뉴는 없다.
- 렌더 스레드의 `RenderThread`(`render.rs`)가 창 상태 전부를 쥔다: egui, 표시·GPU, `canvas: Canvas`, `panels: Panels`, `files: Files`, 설정, 클립보드, 제목, 복구·TDR 상태, `canvas_view: DocumentView`.
- 문서 단위로 이미 떨어지는 것: `Canvas`(`canvas.rs`) = `ugu_session::Session`(history, 레이어·프레임) + 자기 `CacheWorker` 스레드 + split·미리보기·표시 픽스맵 + 보기 상태(배율·위치·회전·반전) + 재생·썸네일. `Canvas::replace`가 창을 두고 문서만 바꾸는 길이다.
- 섞여 있는 것:
  - 도구와 색 기록이 `Session` 안에 있다(`pen`, `eraser`, `fill`, `text`, `colors`, `remembered`, `before_pixel`). `replace`가 `tools()`/`set_tools`로 옮긴다.
  - `Files`(`files.rs`)에 문서 몫(경로, id, 저장 확인 `confirm`/`after_save`, 열기 진행, 복구 설명, 이름 없는 문서 이름)과 창 몫(파일 작업자 스레드 하나, 내보내기, 업데이트 확인, 상태 메시지, 기본 저장 폴더)이 함께 있다.
  - 복구 폴더가 창(프로세스)마다 하나이고 문서 하나를 담는다(`recovery.rs`).
  - `Panels`(`ui/mod.rs`)는 창 몫(독 배치, 단축키, 대화상자)이지만 애니메이션·우글거림 편집 중인 값을 문서에서 가져와 들고 있다.

## 3. 정한 것 (2026-10-12 사용자 결정)

1. 탐색기의 두 번째 실행은 **떠 있는 창의 새 탭**으로 연다(추천과 다름). 단일 실행과 프로세스 사이 전달이 3.0에 들어간다. 방식(이름 있는 파이프 등)은 3단계 뒤에 재고 정한다.
2. 도구는 **창 공용**, 픽셀 모드용 브러시·지우개 칸은 따로(추천대로).
3. 탭은 **순서 바꾸기만**, 떼기는 backlog(추천대로).
4. 문서 수 **상한 없음**, 측정 뒤 다시 본다(추천대로).

아래는 물을 때의 선택지와 추천이다.

1. 탐색기의 두 번째 실행: 지금처럼 새 창(프로세스)인가, 떠 있는 창의 새 탭인가. 새 탭이면 단일 실행과 프로세스 사이 전달(이름 있는 파이프 등)이 필요하다. 추천: 3.0은 새 창 그대로, 탭으로 보내기는 backlog.
2. 도구는 창 공용인가 문서별인가. 클립 스튜디오와 2.2.13(새 문서도 도구 유지)은 공용이다. 추천: 공용. 단, 픽셀 모드 문서와 일반 문서를 오갈 때를 위해 픽셀 모드용 브러시·지우개 칸을 따로 둔다(4절 2).
3. 탭을 끌어 순서 바꾸기, 탭을 창 밖으로 떼어 새 창 만들기. 추천: 순서 바꾸기만 3.0, 떼기는 backlog.
4. 문서 수 상한. 문서마다 `CacheWorker` 스레드와 캐시 예산이 생긴다. 추천: 상한 없이 두되 캐시 예산은 창 전체로 나눈다(4절 5), 측정 뒤 정한다.

## 4. 설계

1. **`Document` 묶음**: `Canvas`와 `Files`의 문서 몫(경로, id, 저장 확인 상태, 저장 뒤 동작, 이름 없는 문서 이름, 복구 설명)을 한 구조체(가칭 `Tab`)로 모은다. `RenderThread`는 `tabs: Vec<Tab>`, `current: usize`를 가진다. `Files`에는 작업자·내보내기·업데이트·메시지만 남긴다. 작업자에 보내는 일과 돌아오는 답에는 탭 id를 붙인다(지금의 `generation`처럼 늦은 답을 거른다).
2. **도구를 `Session` 밖으로**: `Tools`를 창이 쥐고, 획·채우기·글자를 시작할 때 세션에 넘긴다. 이 과정에서 `follow_pixel_mode`/`before_pixel`을 없애고 "일반 브러시·지우개"와 "픽셀 브러시·지우개" 두 칸을 둔다. 현재 문서의 모드가 쓸 칸을 고르므로 모드를 오가도 서로 덮지 않는다. 설정 파일은 두 칸을 따로 저장하고, 옛 설정의 `beforePixel`은 읽어서 옮긴다. `.ugurugu-tools`는 지금처럼 일반 칸만(가설: 픽셀 칸도 넣을지는 3절 2와 함께).
3. **복구**: 창 폴더 아래 탭마다 하위 폴더(`recovery\<창 UUID>\<탭 id>\`), 같은 2세대 쓰기. 복구 목록은 탭 단위로 보이고, 하나를 복구하면 새 탭으로 연다. 옛 형식(창 폴더에 문서 하나)도 읽는다. 쓰기는 현재 탭만이 아니라 바뀐 탭 모두, 지금과 같은 조용한 간격(`QUIET` 3초, `LONGEST` 30초)으로.
4. **표시**: `DocumentView`(GPU 텍스처)는 창에 하나 두고 탭을 바꾸면 그 탭의 표시 픽스맵을 다시 올린다(`upload_all`). 탭마다 텍스처를 두는 것은 바꾸는 시간을 재 보고 정한다(목표: 4096² 문서에서 탭 바꾸기 한 프레임 안, 가설).
5. **캐시와 작업자**: 문서마다 `CacheWorker`가 있다. 보이지 않는 탭의 작업자는 멈추고(새 일 없음), 캐시 예산(`budget.rs`)은 창 전체에서 현재 탭이 먼저 쓰게 한다. 8 작업자(`UGU_WORKER_THREADS=8`)에서 탭 3개·문서 ② 기준으로 메모리와 바꾸기 시간을 잰다.
6. **패널**: 레이어·애니메이션·우글거림 패널이 들고 있는 문서 값은 탭을 바꿀 때 다시 읽는다(지금 `replace` 뒤에 하는 일과 같음). 독 배치·단축키는 창 몫 그대로.
7. **UI**: 캔버스 위 탭 막대(이름, `*`, ×, 가운데 클릭 닫기), 파일 메뉴에 탭 닫기, 창 메뉴에 탭 목록. 단축키는 사용자 지정에 넣는다. 문구는 `strings.txt` → `ts_to_ftl.py`.
8. **닫기·업데이트**: `Action::Close`/`Update`가 저장 안 한 탭을 차례로 묻는 줄을 만든다. 지금 하나짜리 `confirm`을 탭 id가 붙은 줄로 바꾼다.

### 2단계 나누기 (2026-10-12, `070ac66`에서 필드마다 확인)

1단계에서 도구를 `Canvas`로 옮겼으므로 `Canvas`가 창의 캔버스 영역이 되고, 탭은 `Canvas` 안에 둔다(`tabs: Vec<Tab>`, `current`). `Files`의 메서드는 이미 `&mut Canvas`를 받으므로 현재 탭의 파일 상태를 `Canvas`를 거쳐 읽는다. 두 구조체가 따로 탭 목록을 갖지 않게 한다.

| 어디로 | `Canvas` 필드 | `Files` 필드 |
|---|---|---|
| 탭 | `session`, `cache`(4절 5), `split`, `preview`, `text_preview`, `requested`, `display`, `held`, `resume_playback`, `snapshot`, `thumbnails`, `thumbnails_asked`, `reference`, 보기(`scale`, `offset`, `angle`, `mirrored`, `placed`), `playback`(현재 탭만 돈다) | `path`, `id`, `confirm`·`after_save`(탭 id가 붙은 줄로, 4절 8), `unsaved_name`, `unsaved_from`, `opening`, `recovery`의 문서 몫(`written`, `unwritten`, `stored`, 4절 3) |
| 창 | `tools`, `typesetter`, `upload`·`uploaded`(탭을 바꾸면 `upload_all`), `interaction`(바꾸기 전에 끝냄), `modifiers`, `area`, `pixels_per_point`, `hover_eraser`, `drawn_at`, `sample_count`, `notice`, `animation_allowed`, `stamp`(가설: 획 찍기 작업 공간이라 창 하나로 충분), `spare_coverage`(크기가 다르면 버림) | 작업자·이벤트·`owner`, 저장 수(`saves_started`, `saving`), `opened`, `busy_dialog`, 기본 폴더, 내보내기 크기, 메시지(`message`, `failing`, `upcoming`), `close`, `found`·`reading_found`, 내보내기(`exporting` 등, 탭 id를 붙임), 새 문서 대화상자, `updates` |

주의할 점:
- `generation`은 지금 문서를 열 때마다 오른다. 탭마다 두면 탭끼리 같은 값이 나올 수 있으므로 창의 카운터가 탭을 만들 때마다 새 값을 준다. 작업자·클립보드의 늦은 답은 이 값으로 탭을 찾는다(`clipboard.rs`, `files.rs`의 `canvas.generation()`).
- `placed`인 보기는 `set_area`가 영역이 커진 만큼 위치를 옮긴다. 숨은 탭은 그사이 창 크기가 바뀌었을 수 있으므로 탭마다 마지막으로 본 영역을 두고, 돌아올 때 그 차이로 옮긴다.

## 5. 순서

1. 도구를 `Session` 밖으로, 일반·픽셀 칸 분리(4절 2). 지금 동작은 바뀌지 않고 픽셀 모드 왕복만 좋아진다. 시험: 모드 왕복, 새 문서, 실행 취소, 설정 읽기·쓰기, 옛 `beforePixel` 옮기기.
2. `Tab` 묶음과 `Files` 나누기(4절 1), 탭 하나로 지금과 같게 동작. 기존 시험 전부 통과.
3. 탭 여러 개: 새로 만들기·열기·바꾸기·닫기, 같은 파일 다시 열기, 닫기·업데이트 줄(4절 7·8).
4. 복구를 탭 단위로(4절 3), 강제 종료 시험(`tools/kill_probe.py`)을 탭 여러 개로.
5. 캐시·표시 측정과 조정(4절 4·5).
6. Sandbox `gui.ps1`에 탭 단계(새로 만들기 → 그리기 → 새 탭 → 처음 탭으로 돌아와 그림 그대로), 릴리스 노트·도움말.

각 단계는 커밋 전에 fmt → deny → clippy `-D warnings` → test(debug, release). egui 프레임 시험은 `textures_delta`를 비운다.

## 6. 함께 볼 것

- 2026-10-12 사용자 실행에서 도구 설정 패널이 닫힌 채 저장되어 도구를 골라도 설정이 보이지 않았다. 패널을 닫는 길은 그룹의 ×와 창 메뉴뿐이고, 색상 패널을 떼었다 붙이는 시험(위치 6곳)으로는 재현되지 않았다. 패널을 다시 열고 픽셀 모드를 고친 뒤 사용자가 해결됐다고 했다. 다시 보고되면 backlog에 올린다. 탭 막대가 캔버스 위 공간을 쓰므로 독 작업 때 함께 본다.
- 시작 직후 제목에 `*`가 붙은 적이 있다(같은 실행, 원인 미확인, 가설: 복구 또는 픽셀 모드 상태). 탭 이름의 `*`와 같은 판단을 쓰므로 2단계에서 확인한다(backlog B3-76).

### 할 일

1. **현황 캡처**: Windows Sandbox `gui.ps1`에 모든 패널·대화상자(설정 탭 5개, 새 문서, 크기 변경, 내보내기, 복구 안내, 업데이트, 도움말)를 찍는 단계를 넣어, 고치기 전 화면 모음을 만든다. 사용자와 이 모음을 보며 우선순위를 정한다.
2. **디자인 기준**: 색 단계(배경·패널·컨트롤·경계·글자 3단), 간격 단위(4의 배수), 모서리, 그림자, 글자 크기 단계(제목·본문·보조), 포커스·hover·눌림 상태를 `theme.rs`에 토큰으로 정한다. 강조색 설정은 유지한다.
3. **위젯 통일**: egui 기본 버튼을 `widgets.rs`의 버튼(주·보조·위험 단계)으로 바꾸고, 입력칸·선택 상자·색 상자·단축키 입력도 같은 모양으로. 키보드 포커스 표시(backlog B3-41)를 함께 고친다.
4. **설정 다시 짜기**: 왼쪽 목록(아이콘+이름) + 오른쪽 내용의 2단 배치(가설, 1에서 정함), 항목을 묶음 카드로 나누고 설명 글을 조용하게. 단축키 탭은 검색과 충돌 표시. 정보 탭은 판·진단 정보·로그 폴더를 정리.
5. **대화상자**: 새 문서(크기 단추·픽셀 모드), 저장 확인, 내보내기, 크기 변경을 같은 틀(제목, 내용, 아래 오른쪽 버튼 줄)로.
6. **패널과 탭 막대**: 독 머리(손잡이·탭·×), 레이어 목록, 도구 설정, 문서 탭 막대를 같은 기준으로.
7. **확인**: 화면 모음을 다시 찍어 전후 비교, 150%와 100% DPI 둘 다, 한국어·일본어·영어 문구 길이로 넘침 확인. 성능은 UI 프레임 시간이 늘지 않았는지 8 작업자에서 잰다.

순서: 문서 탭 1~2단계(구조)와 따로 진행할 수 있다. 탭 막대 UI(문서 탭 3단계)는 디자인 기준(할 일 2) 뒤에 만든다.
