# 애니메이션 계획: 레이어 키프레임과 셀 애니메이션 (3.2.0)

2026-10-14 작성. 사용자 요청: 그린 캐릭터가 좌우로 오가는 것처럼 움직이게 하는 애니메이션 기능을 3.2.0에 넣는다. 두 가지를 함께 만든다.

- **레이어 키프레임**: 페인트 레이어와 그룹의 위치·회전·크기·좌우 반전을 몇 프레임에 정하면 사이 프레임을 잇는다. 캐릭터가 통째로 오가는 움직임.
- **셀 애니메이션**: 프레임마다 다른 그림(셀)을 보이는 애니메이션 폴더와 어니언 스킨. 팔다리처럼 모양이 바뀌는 움직임. 클립 스튜디오의 애니메이션 폴더와 같은 생각이다.

사용자 결정(2026-10-14): 키 속성은 위치·회전·크기·좌우 반전, 레이어와 그룹 모두, 문서 프레임 상한 60 유지. 2.2.13에는 두 기능 모두 없다(`v2.2.13` 소스에 keyframe·onion 없음). 이 문서는 계획이고, 정한 것은 구현하면서 decisions.md로 옮기고 이 문서는 끝나면 지운다(문서 탭 계획과 같은 방식).

코드 위치는 2026-10-14 `rust/layer-buttons`(`cccf6a7`) 기준으로 읽은 것이다. 측정하지 않은 비용은 **가설**로 적는다.

## 1. 지켜야 할 약속

1. **화소 일치**: 캔버스·재생·내보내기는 같은 `RenderPlan`을 평가하고 원본 크기에서 캔버스와 내보내기가 바이트 같다(decisions.md 2절). 키프레임 변환과 셀 선택은 plan에 들어가고, 모든 렌더 경로(일반, 예산 초과 streamed, 편집 split, 참조)가 **한 함수**로 변환한다. 경로마다 바이트 비교 시험을 둔다.
2. **기존 문서는 그대로**: 키도 셀도 없는 문서는 렌더 결과 바이트, 파일 바이트, 성능이 지금과 같다. 회귀 fixture digest(`crates/ugu-render/tests/regression.rs`)가 바뀌지 않는다. 변환이 항등이면 재샘플을 건너뛴다.
3. **성능 우선, 8 작업자 기준**: 키가 있는 레이어도 레이어 표면은 캐시하고 프레임마다 변환만 한다. 셀은 레이어 id로 캐시되므로 한 바퀴 뒤에는 다시 그리지 않는다. 전후를 `ugu-doc render <file> 8`로 같은 방식으로 잰다.
4. **형식**: schema 1은 출시 뒤 고정이다(ADR 7절). 새 필드는 쓰지 않으면 생략되고, 쓰면 manifest `required`에 기능 이름을 넣어 3.1 이하가 "새 판에서 만든 파일"로 거절하게 한다.
5. **편집 의미**: 레이어에 그리는 편집은 **레이어 공간**에서 일어난다. 화면 좌표와 문서 공간 선택은 현재 프레임의 변환 역행렬로 레이어 공간에 옮긴다. 그래야 움직인 레이어에서도 펜 아래에 그려지고, 다른 프레임에서는 그 선이 레이어와 함께 움직인다.

## 2. 데이터 모델 (`ugu-core`)

### 2.1 키프레임

`PaintLayer`와 `Group`에 같은 필드를 더한다(기본값이면 지금과 같음).

```rust
pub struct Keys {
    /// 회전·크기·반전의 중심, 레이어 공간(문서 좌표).
    pub pivot: [f64; 2],
    /// 프레임 순, 프레임마다 하나.
    pub keys: Vec<Key>,
}
pub struct Key {
    pub frame: u32,
    pub offset: [f64; 2],   // 이동, 문서 px
    pub rotation: f64,      // 도, 시계 방향
    pub scale: f64,         // 1 = 원래 크기, 가로·세로 같이
    pub flip: bool,         // 좌우 반전
    pub ease: Ease,         // 이 키에서 다음 키까지
}
pub enum Ease { Linear, Smooth, Hold }
```

- 프레임 f의 변환 `T(f) = translate(offset) · about(pivot, rotate(rotation) · scale(±scale, scale))`. `Affine`(ops.rs)의 `translation`·`rotation_about`·`scaling_about`·`then`을 쓴다.
- **보간**: 키가 없으면 항등. 키 하나면 모든 프레임이 그 값. 둘 이상이면 앞 키의 `ease`로 다음 키까지 잇는다(`Smooth` = smoothstep, `Hold` = 다음 키 전까지 앞 값). **반복**: 마지막 키 뒤로는 문서 프레임 수만큼 뒤의 첫 키를 향해 잇는다. 그래서 0프레임 왼쪽, 15프레임 오른쪽 두 키만으로 30프레임 왕복이 끊김 없이 돈다. 반전은 수치가 아니라 앞 키 값을 유지하다 키에서 바뀐다.
- 보간은 `ugu-core`의 순수 함수 `Keys::at(frame, frames) -> Affine` 하나로, 렌더·세션·UI가 모두 이것만 쓴다. `f64` 연산만 쓰고 `sin`·`cos`은 회전에 한 번(B3-71의 1ulp 가설과 같은 범위).
- 픽셀 모드 문서는 이동을 정수로 반올림하고, 회전·크기를 쓰면 nearest로 그린다(4.2).
- **한도**(`document::limits`): 키 프레임 < `FRAMES.end()`(60), 한 레이어 키 60개, offset ±32767, scale 0.05~20, rotation −3600~3600, 모두 유한. pivot ±32767. 위반은 새 `DocumentError`.
- 프레임 수를 줄이면(`set_animation`) 새 프레임 수 이상의 키는 같은 undo 단계에서 지운다. 되돌리면 돌아온다.

### 2.2 애니메이션 폴더와 셀

그룹에 노출표를 더해 **애니메이션 폴더**로 만든다. 셀은 그 폴더의 바로 아래 자식 레이어(페인트 또는 그룹)다. 새 레이어 종류를 만들지 않으므로 그리기, 연산 주소(`InsertOp`), 병합, 선 속성, 복사, 썸네일이 지금 코드를 그대로 쓴다.

```rust
pub struct Group {
    // 지금 필드…
    pub keys: Keys,
    /// Some이면 애니메이션 폴더: 프레임마다 자식 하나만 보인다.
    pub cels: Option<Vec<Exposure>>,
}
pub struct Exposure {
    pub frame: u32,
    /// 이 프레임부터 다음 항목 전까지 보일 자식. None은 빈 프레임.
    pub cel: Option<LayerId>,
}
```

- 노출은 **유지(hold)** 방식이다: 항목이 있는 프레임부터 다음 항목 전까지 같은 셀. 첫 항목 전 프레임은 마지막 항목을 이어받는다(반복). 항목이 없으면 아무것도 보이지 않는다.
- 노출표의 셀 id는 그 폴더의 바로 아래 자식이어야 한다(검증). 노출표에 없는 자식은 보이지 않는다. 자식의 `visible`이 꺼져 있으면 그 프레임은 비어 보인다.
- 프레임 수를 줄이면 그 이상의 항목은 같은 undo 단계에서 지운다(키와 같음).
- 셀 레이어를 지우면 그 셀을 가리키는 항목도 같은 단계에서 지운다(`remove_layer`가 폴더를 고침).
- 폴더도 `keys`를 가지므로 걷는 캐릭터(셀)를 통째로 좌우로 옮기는 것은 폴더 키로 한다.

### 2.3 편집과 history

- 키·노출 변경은 `ReplaceLayer`로 한다(`command::update_layer`). `LayerRevisions::compare`는 키와 노출을 보지 않는다. 키는 합성 속성(불투명도와 같음)이라 레이어 표면을 다시 그리지 않고, 노출은 어느 레이어를 보일지일 뿐 셀의 내용은 그대로이기 때문이다. 시험으로 고정한다.
- 새 명령(`command.rs`): `set_key(layer, key)`, `remove_key(layer, frame)`, `set_pivot`, `make_animation_folder(layer)`(현재 레이어를 첫 셀로 감싼 폴더, 0프레임에 노출), `new_cel(folder, frame)`(빈 페인트 셀을 더하고 그 프레임에 노출, 한 단계), `expose(folder, frame, cel)`, `clear_exposure(folder, frame)`.
- `merge_down`: 위·아래 중 하나라도 키가 있거나 둘이 같은 애니메이션 폴더의 셀이면 거절(새 `MergeRefusal::Animated`). 키가 같은 두 레이어 병합은 나중 일로 둔다.
- `duplicate_layer`: 키를 함께 복사한다(레이어 복제가 이미 레이어 전체를 복제). 셀을 복제하면 폴더 안 바로 위에 생기고 노출표에는 넣지 않는다.
- `ungroup`: 그룹 속성(불투명도 등)과 같이 키·노출도 사라진다. 애니메이션 폴더를 풀면 모든 셀이 모든 프레임에 보이게 되므로, 확인을 묻지 않고 undo로 되돌릴 수 있게만 한다(지금 그룹 해제와 같은 규칙).
- 복사(`clip::copy`)는 키를 가져가지 않는다. 붙여넣은 레이어는 키 없는 새 레이어다.

### 2.4 참조 평가기

`semantics.rs`에 두 의미를 더하고 렌더러가 따른다(ADR 2절 방식): (1) 키가 있는 레이어·그룹은 그 프레임의 결과를 `T(f)`로 옮긴 뒤 합성한다(모의 평가기는 정수 이동만), (2) 애니메이션 폴더는 그 프레임에 노출된 자식 하나만 합성한다.

## 3. 파일 형식 (`ugu-io`)

- `PaintDto`·`GroupDto`에 `keys`(`#[serde(default, skip_serializing_if = "Keys::is_empty")]`), `GroupDto`에 `cels`(같은 방식). 키·셀이 없는 문서의 파일은 바이트 같다.
- manifest `required`: 키가 하나라도 있으면 `"keys"`, 애니메이션 폴더가 있으면 `"cels"`. 읽기는 "모르는 required → `Newer`"로 바꾸고 아는 목록에 둘을 둔다. 3.1 이하는 지금처럼 "새 판에서 만든 파일"이라고 거절한다(`deny_unknown_fields` 때문에 required 없이는 "손상된 파일"이 된다).
- `render_revision`은 1 그대로다(기존 화소가 바뀌지 않음).
- `write.rs`의 `Used`, `read.rs`의 `layer()`, 2.x 가져오기(`legacy.rs`)의 `PaintLayer`·`Group` 리터럴, `document.rs`·`command.rs`·`clip.rs`·`restyle.rs`의 리터럴은 `Default`로 채운다.
- ADR(adr-operations-and-format.md) 7절에 필드를 적는다. decisions.md 6절의 "출시 뒤 변경은 새 ADR"에 따라 ADR에 8절 "3.2.0 키프레임·셀"을 더한다.

## 4. 렌더 (`ugu-render`)

### 4.1 plan이 프레임을 받는다

- `RenderPlan::new(document, purpose, frame)`. 프레임을 받아 키를 평가하고 애니메이션 폴더는 노출된 자식만 넣는다. `Step::Paint`와 `Step::End`의 `Composite`에 `transform: Option<Affine>`(항등이면 `None`)을 더한다.
- `RenderPlan.layers`는 이 프레임에 그리는 레이어만이 아니라 **문서의 모든 셀**도 캐시 유지 대상으로 알린다. 지금은 plan에 없는 레이어의 캐시를 버리므로(`render_scaled` retain) 셀을 넘길 때마다 다시 그리게 된다.
- `moves`는 그대로다(획의 우글거림). 키 변환은 레이어 캐시 키에 들어가지 않는다.
- `RenderPlan::new`를 부르는 곳(캔버스 split, 재생 프레임, 내보내기, 썸네일, 클립보드, ugu-doc)이 모두 프레임을 넘긴다. 내보내기는 이미 프레임마다 plan을 만든다(cache.rs `Renders::export`).

### 4.2 변환 함수 하나

- `ugu_render::transform::draw(source, affine, sampling, rect, out)`: 프리멀티플라이 표면을 `affine`으로 `out`의 `rect` 부분에 그린다. `Raster::put_image`·`moving.rs` `Moving::draw`와 같은 Vello 이미지 칠(`document_level()` SIMD 고정)로, 부분 사각형을 그린 결과가 전체를 그린 결과의 그 부분과 바이트 같아야 한다(시험).
- 샘플링은 기존 `quality()` 규칙을 쓴다: 정수 이동·직각 회전·반전은 nearest(Low), 그 밖은 bilinear(Medium). 픽셀 모드는 항상 nearest.
- 축소 재생(`shrink`)에서는 `S·T·S⁻¹`로 축소 표면을 변환한다. 원본 크기만 내보내기와 같으면 된다(decisions.md 2절).
- 0스레드와 8스레드 결과가 같은지 시험한다(`every_thread_count_draws_the_same_pixels`와 같은 방식).

### 4.3 경로마다 넣는 곳

| 경로 | 지금 | 바꾸는 것 |
|---|---|---|
| 일반 `render_scaled` | 캐시한 레이어 표면을 `Source::Tiles`로 행 단위 합성(`composite::evaluate`) | 변환이 있는 레이어는 표면을 4.2로 캔버스 크기 `Source::Whole`에 그려 넘긴다. 변환이 있는 그룹은 그 하위 프로그램을 통째 표면으로 평가하고 변환해 넘긴다(회전은 행 단위가 안 되므로). |
| 예산 초과 `render_streamed`·`Stream` | 그룹을 통째 표면으로 합성 | `Put::Over`·`Put::End`에서 같은 함수로 변환. |
| 편집 `split`·`reduced` | 편집 레이어 표면에 직접 찍고 dirty 사각형만 다시 합성 | 아래 4.4. 변환이 있는 레이어는 `reduced`의 Normal 묶음에 넣지 않고 `alone`으로 둔다(B3-101을 더 넓히지 않음). |
| 참조(채우기·자동 선택) | `Reference::Layer`는 그 레이어만, `Visible`·`Marked`는 문서 | `Layer`는 변환 없는 레이어 공간(편집이 레이어 공간이므로), `Visible`·`Marked`는 그 프레임의 변환을 적용한 문서 공간. 결과 mask를 레이어 공간으로 옮기는 것은 세션(5.1). |
| 썸네일 | 0프레임, 레이어 자기 화소 | 그대로(변환 없이). 셀은 각자 자기 썸네일. |
| 예산 추정 `surface_estimate` | 레이어 표면 | 변환용 캔버스 크기 표면과 변환 그룹의 통째 표면을 더한다. |

### 4.4 움직인 레이어에서 그리기

- 편집 레이어에 변환이 있으면 split은 그 레이어 표면을 레이어 공간 그대로 두고, 합성 때 4.2로 옮긴다. 진행 중 획(live overlay)·도장(`stamp`)·채우기는 레이어 공간 좌표로 그 표면에 그린다.
- dirty 사각형은 레이어 공간 사각형을 `T`로 옮긴 경계 사각형(+1px)으로 다시 합성한다. 그 사각형의 결과가 전체를 다시 그린 결과와 바이트 같아야 한다(4.2 시험).
- 변환이 항등인 프레임에서는 지금 경로 그대로다(시험으로 같음을 확인).
- 비용 가설: 2048² 레이어에서 펜 이동마다 작은 사각형만 변환하므로 pen-up 8ms 목표 안. 잰다(7절).

### 4.5 캔버스 밖

레이어 표면은 캔버스 크기다(`reach`가 캔버스로 자름). 그래서 캔버스 밖에 그린 것은 없고, 레이어를 옮기면 그 가장자리가 비어 들어온다. 캐릭터를 캔버스 안에 그리고 옮기는 쓰임에는 충분하다. 캔버스 밖에서 들어오는 움직임을 위해 표면에 여백을 두는 것은 타일 계산·예산을 바꾸는 일이라 이번에 하지 않고 backlog에 둔다.

### 4.6 어니언 스킨

- **화면 표시만**이다. `RenderPlan`에 넣지 않으므로 내보내기·재생·참조에 들어가지 않는다.
- 현재 레이어가 애니메이션 폴더의 셀이면, 그 폴더의 앞 프레임 n개와 뒤 프레임 n개 렌더(그 프레임의 키 변환 포함)를 색을 입혀 캔버스 표시 아래에 깐다. 기본 앞 1·뒤 1, 불투명도 30%, 앞은 붉게·뒤는 푸르게(클립 스튜디오 관례, 사용자 설정).
- 그리는 일은 캐시 작업자의 새 일 `Job::Onion`(우선순위: split 다음)이 폴더만의 plan(`Reference::Marked`처럼 폴더 하나)을 그 프레임으로 평가한다. 결과는 키 (문서 revision, 폴더, 프레임)로 캐시한다.
- 재생 중에는 끈다.

## 5. 세션 (`ugu-session`)

### 5.1 레이어 공간

- `Session::layer_transform()` = 현재 레이어와 조상 그룹들의 `T(frame)` 곱. `to_layer(point) = layer_transform().inverse()`.
- 그리기(`begin_stroke` 등), 도형, 문자 배치, 채우기 클릭 점은 레이어 공간 좌표로 받는다(앱이 변환해 넘김, 6.2).
- 문서 공간 선택을 획의 clip이나 선택 변형에 쓸 때는 mask를 `T⁻¹`로 레이어 공간에 옮긴다(nearest, `selection.rs`의 기존 변형 함수). 항등이면 지금 그대로 쓴다.
- 대기 변형(선택 변형·붙여넣기)은 레이어 공간에서 일어난다. 변형 상자는 화면에 `T`를 적용해 그린다.

### 5.2 프레임과 셀

- `set_frame`에서 현재 레이어가 애니메이션 폴더의 셀이면, 새 프레임에 노출된 셀로 현재 레이어를 바꾼다(클립 스튜디오와 같음). 빈 프레임이면 폴더를 현재로 둔다.
- 폴더가 현재이고 그 프레임에 셀이 없을 때 그리기를 시작하면, 새 셀을 만들어 노출하고 그 셀에 그린다(한 undo 단계, "새 셀"). 묻지 않는다.
- 이전·다음 프레임, 이전·다음 키로 가기 명령을 더한다.

### 5.3 키 편집

- `set_key_here(layer, change)`: 현재 프레임에 키가 있으면 고치고 없으면 지금 보간 값으로 키를 만든 뒤 고친다(자동 키). 한 undo 단계.
- 레이어 이동 도구의 끌기는 끄는 동안 대기 키로 두고 놓을 때 한 단계로 커밋한다(변형 상자와 같은 방식, Esc는 취소).

## 6. 앱 (`apps/ugurugu`)

### 6.1 타임라인

- 아래 애니메이션 막대를 **타임라인**으로 넓힌다. 머리 줄은 지금 막대(재생, 프레임, 프레임 수, FPS, 접기)를 그대로 두고, 그 아래에 행을 둔다. 접으면 지금 한 줄 막대와 같다(`layout.animation_bar`, 새 설정 `timeline_rows`로 높이).
- 행: 현재 레이어와 그 조상 그룹, 키가 있는 레이어·그룹, 애니메이션 폴더. 열: 프레임 1~N(지금 스크러버 칸과 같은 폭 계산).
  - 키 행: 키 프레임에 마름모. 클릭하면 그 프레임으로, 끌면 키를 옮김, 오른쪽 클릭 메뉴로 보간(직선·부드럽게·멈춤)과 삭제.
  - 셀 행: 노출 구간을 셀 이름 막대로. 칸을 누르고 메뉴에서 셀 고르기·새 셀·비우기.
- 머리 줄에 버튼: 키 추가/삭제(현재 레이어·현재 프레임), 이전·다음 키, 어니언 스킨 켜기, 애니메이션 폴더 만들기, 새 셀.
- 독 패널로 만들지 않는다(독은 왼쪽·오른쪽·떠 있음만 있고, 타임라인은 아래 가로 막대가 맞다). 그래서 `layout.rs`의 `Panel::ALL` 검사(새 패널이 저장된 배치를 초기화하는 함정)를 건드리지 않는다.

### 6.2 입력

- `canvas.rs` `input_point`, `begin_shape`·`drag_shape`, `click_area`, `canvas/text.rs`의 배치·끌기는 `to_document` 뒤에 `session.to_layer`를 거친다. 확대·이동·회전·스포이드·브러시 커서·상태 표시줄 좌표는 문서 공간 그대로다. 브러시 커서 크기는 레이어 크기 키를 곱해 보인다.
- **레이어 이동 도구**(새 도구, 기본 키 V): 현재 레이어·그룹의 내용 경계에 `T(frame)`를 적용한 상자를 그리고, 변형 상자(`canvas/transform.rs`)의 손잡이 계산(`Grip`, `HANDLES`, 회전 15° 스냅, Shift 비율)을 함수로 빼서 같이 쓴다. 끌면 5.3의 자동 키. 상자 아래 막대에 좌우 반전 버튼.
- 레이어 속성(`ui/layers.rs` `properties`)에 "움직임" 묶음: X·Y·회전·크기 숫자 칸과 반전 스위치(현재 프레임 값, 바꾸면 자동 키), 보간 선택, 중심 재설정.
- 레이어 줄에 키가 있으면 작은 표시(우글거림 토글 왼쪽), 애니메이션 폴더는 다른 폴더 아이콘.

### 6.3 단축키 (지금 비어 있는 키, `shortcuts.rs`에서 다시 확인)

| 동작 | 기본 키 |
|---|---|
| 레이어 이동 도구 | V |
| 현재 프레임에 키 추가/삭제 | K |
| 이전·다음 프레임 | `,` · `.` |
| 이전·다음 키 | Shift+`,` · Shift+`.` |
| 어니언 스킨 켜고 끄기 | O |
| 새 셀 | Ctrl+Shift+N |

### 6.4 문구·아이콘·도움말

- `strings.txt`에 세 언어로 넣고 `strings_to_ftl.py`로 만든다. 새 아이콘: 키(마름모), 레이어 이동, 어니언 스킨, 애니메이션 폴더, 새 셀. 동작마다 다른 아이콘을 쓰고 Sandbox 100%에서 16pt로 본다(레이어 버튼 줄에서 배운 것).
- 도움말에 "움직이게 하기" 절: 키로 왕복 만들기(0·15프레임 두 키), 셀로 프레임마다 그리기, 어니언 스킨.

## 7. 시험과 측정

**시험**(고치기 전 실패하는 시험 규칙은 새 기능이라 해당하지 않지만, 각 의미를 시험으로 고정한다)

- core: 보간(직선·부드럽게·멈춤·반복 경계·키 하나·없음), 반전 유지, 한도 검증, 프레임 수 줄이기, 셀 삭제 시 노출 정리, revision이 키·노출로 오르지 않음, 병합 거절, 참조 평가기.
- io: 키·셀 왕복 저장, 없는 문서의 바이트 동일, `required` 이름, 모르는 required 거절, 3.1 판 파일 읽기.
- render: (1) 키·셀 없는 회귀 digest 그대로, (2) 키가 있는 레이어·그룹·클리핑·셀 문서를 일반·streamed·split(편집 레이어 위치 여러 곳)·0/8스레드에서 바이트 같음, (3) 부분 사각형 변환 = 전체의 부분, (4) 내보내기 프레임 = 캔버스 프레임, (5) 어니언 스킨이 내보내기·참조에 없음.
- session: 레이어 공간 입력(움직인 레이어에서 그린 획이 다음 프레임에 함께 움직임), 자동 키, 새 셀 자동 생성, 프레임 바꾸면 셀 따라가기.
- app: 타임라인 키보드 순회·이름(`ui/keyboard.rs`), 좁은 폭 겹침 없음.
- Sandbox: "Keyframes" 단계(레이어 이동 도구로 두 키를 만들고 재생, 두 프레임 화면 비교), "Cels" 단계(폴더·셀 두 개·어니언 스킨 캡처), 화면 모음에 타임라인 추가.

**측정**(8 작업자, release, 같은 PC, 전후 같은 방식, evidence.md에)

- 키·셀 없는 fixture ①~⑤ `ugu-doc render` 시간과 peak가 전과 같은지.
- 키 있는 2048² 레이어 1·4개의 프레임 렌더 시간(변환 비용), 재생 첫 바퀴·이후 fps.
- 셀 10개 폴더의 재생 첫 바퀴·이후, 캐시 메모리.
- 움직인 레이어에서 그릴 때 입력→표시(`latency-probe`)와 pen-up.
- `ugu-doc fixture`에 키·셀 fixture를 더한다.

## 8. 작업 순서

한 브랜치 `rust/animation`에서 커밋을 나눠 쌓고, PR은 둘로 낸다(CI가 약 20분이라 적게).

1. core: `Keys`·`Exposure`, 보간, 검증, 명령, history, 참조 평가기.
2. io: 형식, `required`, 시험.
3. render: plan 프레임, 변환 함수, 경로별 적용, 캐시 유지, 예산, 시험, 측정 → **PR 1**(core·io·render).
4. session: 레이어 공간, 키 편집, 셀·프레임.
5. app: 타임라인, 레이어 이동 도구, 속성, 입력, 어니언 스킨, 단축키, 문구·아이콘·도움말.
6. Sandbox 단계, evidence, decisions(이 계획에서 정한 것), ADR 8절, 릴리스 노트, backlog → **PR 2**.
