# M2 분해: 첫 드로잉 완주 (2026-10-07)

M2 종료 조건(계획 11절): 그리기 → 모션 → 저장 → 재열기 → PNG가 Rust만으로 동작한다. 그리고 다음 두 가지를 지킨다.

- 렌더 결과가 `ugu-core` `semantics.rs`의 의미 시험과 맞는다.
- 입력→표시 지연이 [m0-evidence.md](m0-evidence.md) 1절 값(p50 5.89~6.40 / p95 8.47~9.02ms)보다 나빠지지 않는다.

범위는 [scope.md](scope.md) 3절 기능표의 M2 행이다. 2.2.13 동작은 C++ 소스(`src/render/ClassicStrokeMotion.cpp`, `StrokeRenderer.cpp`, `src/input/StrokeStabilizer.cpp`, `src/io/ExportWorker.cpp`)에서 확인했다.

## 1. 범위

| 넣는 것 | 빼는 것 (단계) |
|---|---|
| 펜(Line 엔진, 둥근 끝, 필압 크기), 지우개(같은 엔진, 앞선 결과에서 지움) | 마커·에어브러시·스프레이, 사각 끝 (M4) |
| 손떨림 보정(1 Euro filter, 세기 0~100%) | — |
| 모션 Classic 1종 | Smooth·Stepped·끊어진 선 (M4) |
| Paint 레이어: 추가·삭제·이동·이름·표시·불투명도·아래로 병합 | 그룹·클리핑·Normal 외 합성 모드 (M3) |
| 타임라인: 현재 프레임, 재생/정지, 프레임 수·FPS·흔들림 양 | 프레임별 편집 기능 (해당 없음) |
| 새 문서·열기·저장·다른 이름으로 저장, 닫기 전 확인 | 자동복구 (M5) |
| PNG (현재 프레임) | JPEG·GIF·WebP (M5) |
| 확대·축소·이동(마우스) | 회전, 터치 (M5) |
| 고정·크기 조절 패널 | 도킹 (M5) |

M2 앱이 렌더하지 못하는 연산(채우기·이미지·선택·자르기·리사이즈)이나 그룹, Normal 외 합성 모드가 들어 있는 `.ugu2`는 열지 않는다. 대신 "이 빌드가 아직 그리지 못하는 기능이 있다"고 안내한다. 틀린 그림을 보여 주거나 그 상태로 다시 저장하는 일을 막기 위해서다(사용자 결정 3).

## 2. 결정 (2026-10-07 사용자 확인)

1. **모션:** 2.2.13 Classic의 수식·상수·해시(SplitMix64 기반 `signedValue`·`smoothValue`)를 `render_revision` 1의 규약으로 고정한다. 움직임의 느낌은 같고, 수치는 골든 값 시험으로 C++ 구현과 대조한다. 픽셀 단위 호환은 약속하지 않는다(계획 5.3절).
2. **필압이 변하는 획:** 점마다 원을, 이웃 점 사이에는 두 원에 접하는 사다리꼴을 두고, 그 합집합(non-zero)을 한 번 채운다. 2.2.13은 점마다 조각을 따로 합성해서 반투명 획의 겹친 곳이 진해졌다. 3.0은 획 전체가 고른 불투명도를 갖는다.
   - 구현하며 정한 것: 필압이 일정한 획도 같은 합집합으로 그린다. Vello는 겹친 조각의 coverage를 더하므로, 합집합의 안티에일리어싱 가장자리가 Vello stroker의 둥근 끝 선보다 평균 약 0.1px 진하다(모양 안쪽·바깥은 같음, `the_union_has_the_shape_of_a_round_stroke`). 필압 범위로 방식을 나누면 마우스 획과 펜 획의 굵기가 달라지고 필압이 조금만 바뀌어도 외관이 바뀌므로, 한 방식으로 통일했다. 중심선은 표본을 잇는 직선이다(표본 간격 2~5px).
3. **M2가 그리지 못하는 내용:** 열기를 거절하고 안내한다.

2.2.13을 그대로 따르는 기본값:

- 문서: 1024×768, 흰 배경, 30프레임, 25 FPS, 흔들림 1.6
- 펜: 폭 6, 검정, 필압 크기 0.8, 안티에일리어싱 꺼짐(켜기 가능)
- 지우개: 폭 6, 안티에일리어싱 켜짐
- 보정: 세기 0
- 그리는 동안: 재생을 멈추고, 현재 프레임의 모션으로 그린다

안티에일리어싱 끄기는 Vello CPU의 `set_aliasing_threshold`를 쓴다.

## 3. 파일 형식 변경

`.ugu2` schema 1은 아직 배포하지 않았다. 그래서 3.0 첫 배포 전까지는 schema 번호를 올리지 않고 필드를 추가한다. M1에서 만든 fixture는 `ugu-doc`로 다시 만든다.

| 위치 | 추가 |
|---|---|
| 획 `brush` | `size_dynamics`(0~1), `wobble_scale`(0~2) |
| 문서·레이어·section `wobble` | `style`(M2는 `"classic"`만) |

## 5. 의미 시험과의 대응

`semantics.rs`는 사각형 획과 "홀수 프레임에 오른쪽으로 amount만큼" 움직이는 가짜 모션으로 의미를 고정한다. 실제 렌더러에 같은 문서를 넣어 픽셀을 그대로 비교할 수는 없다. 그래서 M2-3은 같은 성질을 실제 획·실제 모션으로 다시 확인한다.

| 의미 시험 | M2 렌더러 시험 |
|---|---|
| `an_eraser_reaches_only_what_came_before_it` | 같은 배치. 지우개 앞의 획은 지워지고 뒤의 획은 남는다(획 안쪽 화소로 확인) |
| `merging_keeps_every_frame_and_each_eraser_in_its_own_layer` | 불투명도·wobble이 다른 두 레이어를 병합하기 전과 후, 모든 프레임에서 문서 렌더가 허용 오차 안에서 같다 |
| `an_eraser_added_after_a_merge_reaches_both_layers` | 같은 배치 |
| `merging_refuses_what_it_cannot_keep` | 렌더와 무관(`ugu-core`에서 이미 확인) |
| 선택 변형·채우기·자르기·리사이즈 | 해당 연산을 렌더하는 단계(M4)에서 같은 방식으로 추가 |

| 항목 | 기준 | 비교값 |
|---|---|---|
| 입력→표시 | 나빠지지 않음 | m0-evidence 1절 Rust p50 5.89~6.40 / p95 8.47~9.02ms (C++ 9.62~10.89 / 12.88~13.43) |

| 재생 | 2048² 표준 문서 30fps, 2.2.13 이상 | 2.2.13은 ③을 빼면 처음부터 25fps |
| 저장·내보내기 중 UI | UI 스레드에서 직렬화·인코딩·전체 렌더 없음 | 2.2.13 UI 응답 p95 0.4ms 이하 |

측정은 m0-evidence 1절의 방식을 따른다(PresentMon `--no_track_input`, `latency-probe --warmup 150`, 누락이 있는 실행은 버림).
